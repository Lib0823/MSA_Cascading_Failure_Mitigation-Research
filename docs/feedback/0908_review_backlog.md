### A1. 전파성 조건의 판정 규칙이 없다 — proposal §4-2

원문: *"v의 SLO 위반이 이웃(상류) 서비스의 선행 열화에 뒤따를 때만 positive로 본다."*

자동 역라벨링 코드를 짜려면 셋이 필요한데 전부 없다.

- "선행 열화"의 판정 지표와 임계
- "뒤따른다"의 허용 시간창
- 상류를 몇 hop까지 보는가 (`hop`은 §2-C의 `apply_point` 논의에만 등장하고 라벨링 맥락에는 없음 — grep 확인)

**왜 이월 항목이 아닌가**: E6이 이월한 것은 *"구체 수치(Δ, 임계값, 샘플링 간격, 장애 파라미터)"*다. hop 범위와 시간창의 **존재 여부 자체**는 실측으로 정해지는 값이 아니라 설계 결정이며, 이 규칙이 라벨 전체를 생성한다. 심사에서 *"전파인지 아닌지를 어떻게 판정했나"*에 대한 현재 답은 "이웃이 먼저 나빠졌을 때"뿐이다.

### A2. train/val/test 분할 설계가 없다 — 전 문서

`split`·`hold-out`·`교차검증` grep 0건. (`분할`은 7건 매치되나 전부 "관련연구 3분할"이라 데이터 분할과 무관하다.)

1Hz 샘플링이면 t와 t+1 스냅샷이 거의 동일하다. 랜덤 분할하면 test 샘플의 이웃이 train에 있어 **사실상 답을 보고 맞힌다.** §4-2가 feature 윈도우 ↔ 라벨 창 누수는 정확히 막아놨는데 **분할 누수는 통째로 비어 있다.**

방향: **에피소드 단위 분할**이 최소, **주입 지점 단위 분할**(train에서 본 적 없는 서비스에 주입한 에피소드를 test로)이면 "본 적 없는 장애에도 일반화"를 주장할 수 있다.

### A3. "mₐ는 baseline 실험의 부산물"이 성립하지 않는다 — proposal §4-5

원문: *"즉 mₐ 측정은 별도 실험이 아니라 계획된 baseline 실험의 부산물이다."*

baseline 실험에서 Policy Engine을 돌리려면 `θₐ`가 필요하고, `θₐ = Dₐ·Rₐ/(mₐ·L − Dₐ(1−Rₐ))`는 `mₐ`가 있어야 계산된다. **mₐ를 얻으려면 조치를 발동해야 하는데, 조치 발동에 mₐ가 필요하다** — 순환이다.

해소: mₐ 측정은 Policy Engine 없이 **open-loop 강제 조치**로 한다(장애 주입 → 정해진 시각에 조치 a를 무조건 실행 → SLO 회복분 측정). 부산물이 아니라 **선행 단계**이므로, 실험 순서 서술을 고쳐야 한다.

### A4. baseline 3과 5가 같은 실험 — proposal §4-3

```
3. LSTM 기반 예측 + 동일 Policy Engine
5. FIRM류: 조치 공간은 본 연구와 같으나 위상을 반영하지 않는 예측기로 구동
```

5번은 3번의 상위집합이다 — LSTM은 "위상 미반영 예측기"의 인스턴스이고, "동일 Policy Engine"은 "조치 공간이 같다"를 함의한다. **3번 외의 인스턴스가 지정되지 않아 실질적으로 같은 실험이 된다.** FIRM의 실제 구분점은 위상 미반영이 아니라 **RL 기반 조치선택**이므로, 5번을 살리려면 그것을 구현해야 하고 비용은 자릿수가 다르다.

같은 문장이 언급하는 **"2×2 실험 설계"는 문서 전체에서 이 한 번만 나오고 두 축이 정의되지 않았다.**

그리고 **baseline 1·2의 조치 공간도 정의되지 않았다** — 1번은 "반응형 K8s HPA만 사용", 2번은 "규칙 기반 임계치 Policy"가 서술의 전부다. 2번이 5종 조치를 손으로 그은 임계값으로 쓰는 것인지 스케일링만 하는 것인지에 따라 baseline 3과 겹칠 수도 있다.

### A5. 데이터 수집 중 Tier 1 on/off 구분이 없다 — proposal §2-D

Tier 1 로컬 반사는 *"상시 on"*이다. 데이터 수집 중에도 켜져 있으면 **전파가 일어나기 전에 CB가 잘라버려 positive 라벨이 생성되지 않는다.** 학습시키려는 현상을 시스템이 스스로 지우는 구조다.

수집 시 off / 평가 시 on의 구분이 필요하며, 이는 실험 통제가 아니라 **데이터가 존재하느냐의 문제**다. 문서 어디에도 언급이 없다.

### A6. SLO 위반 판정의 집계 창이 없다 — proposal §4-2

§4-2는 *"P99 응답시간 > 임계 또는 에러율 > 임계"*라 적지만 **P99를 어느 구간에 대해 계산하는지가 없다.** 문서의 `윈도우`는 전부 feature 슬라이딩 윈도우이고 판정 창은 그와 별개다.

노드 타입별 요청률·요청 길이가 자릿수 다르므로(일반 수십 ms / LLM 수 초) 같은 창에서 표본 수가 크게 갈려, LLM 노드의 분위수 추정이 특히 불안정해진다.

### A7. feature 윈도우 길이 W가 어느 미확정 목록에도 없다

`윈도우 길이`·`윈도우 크기`·`window size` grep 0건. E6이 이월한 목록(Δ·임계값·샘플링 간격·장애 파라미터)에도 W는 없다. Δ·간격과 달리 **관리 대상으로 등록조차 되지 않았다.**

### A8. §2-B가 L을 실측 대상으로 지시한다

원문: *"L·Dₐ·Rₐ·mₐ의 실제 수치는 실험 튜닝으로 이월하며…"*

**L은 소거되므로 값이 필요 없다.** θₐ의 분자·분모를 L로 나누고 `dₐ ≔ Dₐ/L`로 두면

```
θₐ = dₐ·Rₐ / ( mₐ − dₐ·(1−Rₐ) )
```

조치 채택 조건 `E[비용|a] < p·L`도 양변을 L로 나누면

```
p·[ (1−mₐ) + dₐ ] + (1−p)·dₐ·Rₐ  <  p
```

즉 **의사결정 전체가 L에 대해 scale-free다**(난수 20,000회 검증 — θₐ 불변 + 조치 선택 동치). 실측할 자유 파라미터는 조치 5종 × (`dₐ`, `Rₐ`) + (장애유형 × 조치)별 `mₐ` + `κ`이며 L은 포함되지 않는다. 현재 서술은 **불필요한 측정을 지시**하고, 동시에 "파라미터가 많다"는 인상을 과장한다.

### A9. §4-4의 "N회 반복 실행" 적용 범위 — proposal §4-4

원문: *"각 baseline 및 본 연구 방식은 동일 조건에서 N회(예: 5~10회) 반복 실행하며…"*

같은 §4-4 목록에 ECE·reliability diagram·lead time이 함께 있는데, 이들은 **고정 test set 위에서 오프라인으로 계산**되는 지표라 "클러스터 N회 반복 실행"과 층위가 다르다. 반복의 의미가 지표군마다 다르다는 구분이 없어, 읽으면 모든 지표가 같은 실행 프로토콜을 따르는 것처럼 보인다.
