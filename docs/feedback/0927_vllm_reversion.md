# LLM 서빙 엔진 재전환 — Ollama → vLLM (J5 부분 번복)

> 작성일: 2026-09-27
> 성격: 자체 검토 결과이며, 지도교수·리뷰어 의견이 아니므로 인용·귀속하지 말 것.
> **상태: 조건부 채택.** **확인 A**(E1 재확인)를 통과하면 확정하고, 실패하면 Ollama 유지로 자동 복귀한다.
> **⚠️ 우선순위: 이 문서 전체가 게이트 ② (DB 캘리브레이션) 다음이다.** 아래 "확인 A·B"는 프로젝트 게이트 ①~③ 과 **별개의 사전 확인**이며, 게이트 번호를 부여하지 않는다(번호 충돌 방지).
> 발단: 지도교수 후보 연구실(서강대 DISCOS Lab, 김영재 교수) 연구 방향성과 본 연구의 부합도 검토 → **지도 요청 방침 확정(§0)**. 근거 자료는 연구실 소개 자료(2026)이며 면담 전이다.
> 범위: [environment](../../research/environment.md) §2-2 / [proposal](../proposal.md) §2-C·§4-1·§4-4·우려 9~15 / [challenges](../../research/challenges.md) J5·E1·E2 / [timeline](../../research/timeline.md) 예산표.

> **번복 범위는 J5의 절반이다.** J5는 ①LLM 노드의 **역할 승격**(= Scale-out이 불가능한 노드)과 ②**구축 방식 경량화**(vLLM → Ollama) 두 가지를 담고 있다. 이 문서는 **②만 번복**한다. ①은 그대로 유지되며, 오히려 이 문서의 §3이 그것을 재확인한다.

## §0. 전제 — 지도교수 방향

**김영재 교수(서강대 컴퓨터공학과, DISCOS Lab 공동 디렉터)께 지도를 요청한다.** §1-2는 이 방침 위에서만 성립하므로 여기에 먼저 기록한다.

| | |
|---|---|
| **부합 판단** | 주제(MSA 연쇄 장애·복원력)는 랩 포트폴리오에 **없다.** 그러나 **방법론은 정면으로 겹친다** — 성능 측정 설계, SLO 기반 자원 의사결정, LLM 서빙. 특히 LLM-Pilot(CCGrid'26)이 *제약 위반 후보 필터링 → 비용효율 최적화 → `argmax`* 구조로, 본 연구 Policy Engine(*`ℓₐ ≥ L_pred` 배제 → 기대비용 → `argmin`*)과 **동형**이다 |
| **학회 라인** | PC 활동이 ICDCS·CCGrid·MASCOTS·Euro-Par·ICPP — GRAF(CoNEXT)·FIRM(OSDI)·DeepScaler(ASE) 계열이 실리는 자리다. **포트폴리오에 없을 뿐 심사 못 할 영역이 아니다** |
| **주제는 바꾸지 않는다** | 랩 코어 주제(KV 캐시 압축·CXL·DPU)는 **실무 역량 전이(1순위 목표)로의 전이율이 낮고**, 2026-09-24로 닫힌 설계가 매몰된다. 주제를 유지하고 **서술 프레임만** 클라우드 자원·SLO 의사결정 쪽으로 정렬한다 |
| **기대하는 지도** | 도메인(MSA·백엔드)이 아니라 **측정 설계와 논문화.** 본인의 강점과 겹치지 않는 쪽이므로 조합으로서 유효하다 |
| **면담에서 그을 선** | *"이기종 노드를 하나의 정책 프레임으로 다룬다"* 는 주장은 **한다.** *"LLM 추론 노드의 대응을 개선한다"* 는 주장은 **하지 않는다** — §3·R-c와 같은 방어선이다 |
| **상태** | **요청 방침만 확정.** 수락 여부·AX대학원 지도 가능 여부·랩 출석 요구는 미확인이며 §8-3에 미결로 둔다 |

> ⚠️ **근거 자료는 연구실 소개 자료(2026) 1부다.** 실제 지도 스타일과 특수대학원 학생 수용 방침은 확인되지 않았다. **포트폴리오와 학회 라인에 근거한 판단이지 지도 경험에 근거한 판단이 아니다.**

## §1. 왜 되돌리는가 — 전제 두 개가 무너졌다

J5의 판단(120~160h → 10h, 재설계 전체의 단일 최대 절감)은 그 시점에서 옳았다. 번복하는 것은 판단의 품질이 아니라 **전제의 유효기간** 때문이다.

### 1-1. E1(vLLM sm_120 빌드 실패)이 낡은 리스크일 수 있다

J5는 E1·E2를 "소멸"로 처리했는데, 정확히는 **회피**였다. 리스크 자체는 여전히 존재하되 우회한 것이다.

문제는 그 리스크 평가가 2025년 하반기 기준이라는 점이다. vLLM의 Blackwell 지원은 이후 공식 휠(CUDA 12.8+)로 정리되었으므로, **2026-09 현재 `pip install vllm`으로 해소되어 있을 가능성이 높다.** 그렇다면 120~160h라는 비용 전제 자체가 무효다.

> 이것은 D14·D15·J6·J14에서 반복된 **원문 확인 원칙을 환경 리스크에 적용**하는 것과 같다. 문헌뿐 아니라 **환경 가정에도 유효기간이 있다.**

### 1-2. R2의 "심사위원 미상" 전제가 무너진다

미채택 (B)와 R2의 논거는 *"심사위원이 LLM 서빙 전문가 기준으로 평가하게 되어 KCI 목표 대비 요구 수준이 과도해진다"* 였다. 이 판단은 **심사위원 구성을 모르는 상태**에서 내려졌다 — R5가 *"지도교수 부재로 사전 확인 불가"* 라고 명시한 그대로다.

**§0에서 지도를 요청하기로 한** 연구실의 포트폴리오 절반이 LLM 추론·KV 캐시다(AegisKV·PAVE·LM-CXD·Cross-KV·LLM-Pilot). 이 방향으로 지도교수가 정해지면:

| | Ollama 유지 | vLLM 전환 |
|---|---|---|
| *"왜 Ollama인가"* 질문 | **나온다** | 나오지 않는다 |
| 그때의 답 | "구축 시간" — 상대가 매일 하는 일이므로 **가장 약한 답** | 해당 없음 |
| 통제 변수 증가 부담 | 없음 | **지도 내용으로 흡수됨** |

즉 **Ollama는 더 이상 방패가 아니다.** 전문가가 심사석에 앉는 상황에서는 회피가 성립하지 않고, 회피 사실 자체가 질문거리가 된다.

## §2. 기술적 근거 — Brownout 기전이 엔진마다 다르다

이것이 문서 수정의 실질적 사유다. 종전 서술이 **틀린 기전을 함의**하고 있었다.

| | Ollama (llama.cpp) | vLLM |
|---|---|---|
| 동시 처리 | `OLLAMA_NUM_PARALLEL` 슬롯 **정적 할당**. `n_ctx`를 슬롯 수로 분할 | PagedAttention — KV 캐시 **블록 단위 동적 할당** |
| `max_tokens` 축소의 효과 | 슬롯 **점유 시간 단축** → 회전율↑ → 큐 대기↓ | 캐시 점유 축소 → **동시 수용 요청 수 증가** + 서비스 시간 단축 |
| 기전의 성격 | 대기행렬 서비스 시간 | **자원 압박 완화** |
| 포화 시 거동 | 큐가 길어진다 | 캐시 압박 → preemption → 재연산 |
| 프로덕션 대표성 | 낮음 | **높음** (vLLM·SGLang·TGI 계열) |

**두 엔진 모두에서 Brownout은 작동한다. 기전이 다를 뿐이다.** 따라서 이 전환은 "실험이 성립하지 않아서"가 아니라 **"실험이 현장으로 건너가는 다리를 넓히기 위해서"** 다.

### 2-1. 이것이 직접 고치는 문서 결함

- **[environment](../../research/environment.md) §2-2의 근거 간극** — 현재 서술은 *"2티어 캐스케이드가 필요 없어져서"* 인데, 이는 **폴백 모델을 뺀 이유이지 vLLM을 뺀 이유가 아니다.** 논리 간극이 그대로 남아 있었다.
- **[proposal](../proposal.md) §2-C의 Brownout 기전 서술** — *"Ollama에서 실제로 지연이 감소하므로 실측으로 성립한다"* 는 현상 서술에 그친다. 기전을 적지 않아 방어력이 낮다.
- **우려 13(소형 모델 일반화)의 방어 부담** — 현재 방어는 *"절대 규모는 실험 환경 제약에 따른 선택"* 하나인데, 엔진까지 비표준이면 **한정 항목이 둘로 늘고 서로 증폭한다.** "3B 소형 모델"과 "3B 소형 모델 + 비프로덕션 엔진"은 무게가 다르다.

## §3. 바뀌지 않는 것 — 범위 통제

이 전환이 **연구의 주장을 키우지 않는다**는 점을 명시한다. 여기가 흐려지면 미채택 (B)로 미끄러진다.

| 항목 | 상태 |
|---|---|
| H2 (유일한 증명 대상) | **불변** |
| H5a · H5b · H6 · H7 | **불변** — 엔진과 무관 |
| `m_scale-out = 0` (S2) | **불변** — 이는 **레플리카 1 고정이라는 설계 결정**에서 나오지 엔진에서 나오지 않는다 |
| H4의 위상 | **불변** — Brownout이 LLM 노드에서 통한다는 것 자체는 §0-2가 이미 *"학술적 신규성이 아니라 주장의 두 번째 실증 사례"* 로 한정했다 |
| 미채택 (A) LLM 에이전트 Policy Engine | **기각 유지** |
| 미채택 (B) LLM 서빙 전용 프레임워크 전환 | **기각 유지** |
| §0-4 무게중심 유지 원칙 | **유지** — 제목에 넣지 않고 초록에만. LLM 노드는 여전히 **검증 대상**이다 |

> **올라가는 것은 기여가 아니라 외적 타당성(external validity)이다.** 증거의 질이 개선되는 것이지 주장이 커지는 것이 아니다. 심사에서 이 구분을 먼저 말하는 것이 우려 9(유행 편승) 방어와 정합한다.

## §4. 비용

| 항목 | 종전 (Ollama) | **전환 후 (vLLM)** | 증분 |
|---|---|---|---|
| 설치·서빙 기동 | 5~10h | 5~10h *(E1 해소 전제)* | 0 |
| 통제 변수 설계·정당화 | ~0 (손잡이 2개) | **5~10h** (`gpu_memory_utilization`·`max_num_seqs`·`max_model_len`·스케줄러) | **+5~10h** |
| 모델 준비 (AWQ/FP8 3B) | `ollama pull` | 별도 준비 | +2~3h |
| **합계** | **10h** | **약 20~25h** | **+10~15h** |

**예산 영향: 445h → 약 455~460h.** 가용 400~500h의 상한 쪽으로 더 붙는다. 이 증분은 **확인 A 통과를 전제로 한 값**이며, 실패하면 120~160h로 되돌아가므로 그 경우 전환을 철회한다.

> **VRAM은 쟁점이 아니다.** 3B를 AWQ/FP8로 올리면 가중치 2~3GB, 잔여 약 5GB가 전부 KV 캐시다. 8GB로 충분하며 **GPU 교체는 불필요**하다. 5060 Ti의 8GB·16GB는 같은 GB206·sm_120이므로 **VRAM 증설로는 E1이 해소되지 않는다.** 증설 우선순위는 여전히 **CPU 코어**다([environment](../../research/environment.md) §1).

## §5. 전제 조건 — 선행 확인 2건

> 프로젝트의 게이트 ①~③ 과 혼동하지 않도록 **번호 대신 A·B로 표기**한다. 둘 다 **게이트 ② (DB 캘리브레이션) 이후**에 수행한다 — S1이 H4의 절반이자 H5b의 근거이므로 S2보다 하중이 크다.

### 확인 A — E1 재확인 (30분) · 전환의 가부

```
pip install vllm
vllm serve Qwen/Qwen2.5-3B-Instruct-AWQ
```

- **통과** → 전환 확정. E1·E2를 "회피"에서 **"해소"** 로 갱신
- **실패** → 전환 철회, Ollama 유지. 단 §2-1의 근거 간극은 **별도로 수정한다**(통제 논거로 교체, 2h)

어느 쪽이든 낡은 전제가 정리되므로 **결과와 무관하게 수행 가치가 있다.**

### 확인 B — Brownout 실효 스모크 (3~5h) · 레버의 존재

**엔진 선택과 무관하며, 확인 A보다 우선한다.**

- **묻는 것**: 부하 포화 상태에서 출력 토큰 상한을 축소했을 때 **TTFT p99가 실제로 떨어지는가**
- **방법**: 서빙 엔진 단독. 동시 요청 N개를 출력 상한 큰 조건 / 작은 조건으로 고정 반복, TTFT·TPOT 백분위수 대조
- **판정**: 유의한 차이가 없으면 **S2의 Brownout 레버 자체가 성립하지 않는다.** 이 경우 엔진 논쟁이 아니라 S2 설계를 재검토해야 한다
- **부산물**: LLM 노드 SLO 기준값(무부하 TTFT·TPOT 실측의 배수, §4-4)이 함께 확보된다

> 확인 A는 *"어느 엔진을 쓸 것인가"*, 확인 B는 *"레버가 존재하는가"* 를 묻는다. **후자가 실패하면 전자는 의미가 없다.** 순서를 지킨다.
